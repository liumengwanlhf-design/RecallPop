# 0.6-test 行为与验证说明

本说明把个人测试记录整理为可公开的行为边界，不包含个人牌组标识、设备进程标识、媒体路径、截图或调试日志。运行源码保持与现有最终测试 APK 对应。

## 行为边界

前台服务由用户明确启动，独占自动计时、取卡和单卡展示。普通已解锁卡使用普通应用悬浮窗；锁屏卡使用内部、不可外部调用的 Activity。主动“复习一张”与自动服务分开，但共同避免并发取卡和重复评分。

持续使用的随机间隔为 120–300 秒。锁屏、熄屏、停用、服务中断、取卡、已有卡面、本应用设置和主动复习期间暂停累计；恢复不计离线时间。解锁事件遇到保护期会丢弃，不到期补发；持续使用计时到期后可等待保护结束。卡面结束保护 90 秒，自动实际展示每日最多 150 次。主动入口不消费自动配额。未答退出不评分、不增加完成统计。

可选亮屏模式默认 09:00（包含）到 23:00（不包含），熄屏后随机请求 5–10 分钟。设置仅接受同日开始早于结束，以及 1–60 分钟且最短不大于最长的间隔。跨过结束时段会延至下一允许时段，达到日上限则等次日，不补发多张。

亮屏使用 `setExactAndAllowWhileIdle`。请求间隔不等于实际投递间隔；Android Doze 的节流和厂商限制都可能延迟。闹钟执行时仍检查模式、时段、权限、保护、配额、熄屏与单卡状态；先取得真实卡片并检查媒体，再启动卡面。无卡或媒体失败不会展示空卡。实际可见、有焦点且屏幕已亮后才计展示。

锁屏卡保持系统锁，允许用户回答。初始无人触摸时暂保持亮屏最多 30 秒，再退出卡片；第一次真实触摸会解除暂保持并取消该次退出计时，之后由系统屏幕超时管理。未答离开或熄屏不评分。短时 CPU 唤醒锁只保护取卡与启动确认，硬超时 30 秒，在成功、失败和停止路径释放。

所有 AnkiDroid 读写使用作用域内的 unstable content provider client 并关闭游标。读取遇到 `DeadObjectException` 只有限重取一次；评分只提交一次，不重试未知写入结果。读回确认该卡 `reps + 1` 后才更新本应用完成统计。评分结果未知时由用户在 AnkiDroid 核对，不能承诺撤销已经发出的请求。

## 已有证据

原开发环境完成离线 `assembleDebug`、版本与同证书检查。主机检查覆盖保护和日上限边界、计时暂停与恢复、1000 个随机范围样本、完成统计并发与跨日、11 项亮屏时段与设置边界。官方 AnkiDroid 2.24.0 字段合同和只读源码边界检查也通过；源码检查不能代替 Android 生命周期验收。

中间包曾在 AnkiDroid 被系统结束后保持伴侣前台进程，并冷取到一张卡。此证据只属于当时中间包，不能宣称最终包所有流程已重测。

一台 realme UI 7 设备上，原生电池权限齐全时仍出现闹钟被厂商延迟和后台页面被拦截。分别开启相关应用的厂商后台行为、后台弹出与锁屏显示许可后，正常十秒测试实际取卡并在锁屏上显示，系统锁未解除。这说明多个权限彼此独立，不能保证其他 ROM 行为相同。

最终 APK 已完成以下短流程：用户真实首触取消初始退出计时，用户自行选择评分，API 确认 `reps + 1` 后完成计数增加一次；另一张卡全程无人触摸，约 30 秒退出且未提交评分；结束并熄屏后正常安排了下一轮约 9 分 34 秒的任务，没有观察到该次安排被策略调整。安排成功并不证明自然闹钟后来实际投递。

## 尚未完整验证

自然 5–10 分钟实际投递、拔 USB 长期待机、重启及平台恢复、运行通知的停止按钮、全部卡型和音频、AnkiWeb 同步与 Android lint 均未完整验收。旧版偶发卡面消失也未完整复现。没有开机接收器，重启后需要手动启动。

主界面十秒测试仍遵守生产限制，不修改正常间隔。调试包另有受 `android.permission.DUMP` 限制的开发广播，可以绕过部分保护，但不接受评分参数，也不能作为自然计时、生产时段或长期待机的证据。普通使用与安装不需要这些开发调用。

# RecallPop · 随时复习

一个实验性的 Android AnkiDroid 伴侣：把短轮复习放进解锁、持续使用手机和自愿开启的锁屏亮屏时刻。每轮默认一张，也可选择最多3、5、10次成功评分。卡片、到期安排、评分、FSRS 和复习历史仍由 AnkiDroid 管理，RecallPop 不维护另一套卡库或调度器。

当前版本为 **0.82-test**（versionCode 16），GitHub 标签为 `v0.82.0-test`。适合愿意自行检查行为的试用者；本项目与 Anki / AnkiDroid 官方没有隶属关系。

[下载 0.82 测试 APK](https://github.com/liumengwanlhf-design/RecallPop/releases/tag/v0.82.0-test) · [下载站](https://pop.382910.xyz/) · [Pages 备用入口](https://pop-382910.pages.dev/) · [版本记录](CHANGELOG.md) · [0.82 验证说明](docs/0.82-testing.md)

项目原发布名为 AnkiGate，现更名为 RecallPop。安装后的显示名称仍为“Anki 解锁复习”，包名仍为 `dev.ankigate`；下载文件名的变化不影响应用数据。

0.82 增加系统复习检查计划、有限的系统退出说明，以及两分钟媒体目录索引复用。它包含0.72–0.81的评分队列修复、取卡取消、批次复习和更新安装交接修复；详细变化见 [CHANGELOG](CHANGELOG.md)。

## 它会做什么

- 解锁优先提醒；已解锁且持续使用时，以随机 2–5 分钟的累计间隔尝试开始一轮到期卡复习。两种模式可分别关闭。
- 可选的熄屏亮屏复习：默认每天 09:00–23:00，熄屏后随机请求 5–10 分钟一次。时段和间隔可在界面修改，系统待机与厂商策略可能推迟实际展示。
- 每轮最多1、3、5、10次确认成功的评分，默认1。按 AnkiDroid 当时的队列逐张读取；“重来”和“困难”也推进一格，同一张被 Anki 再次安排时可再次出现。达到上限、没有到期卡或退出即结束，不等待未来卡、不预造固定卡序。
- 整轮结束后保护 90 秒，每天自动展示最多 150 张，按每张实际显示计数。未答关闭只计展示，不评分、不计完成。
- “开始本轮复习”提供主动入口，不依赖自动服务、不消耗自动展示配额。评分由用户点击，并真实提交到 AnkiDroid；确认后才计本应用的完成次数。
- “今日达标复习”默认只计 API 确认成功的“良好”和“简单”；可改为所有评分或仅简单。“困难”和“重来”仍正常提交，新达标统计不回填0.6旧记录。
- 主界面和常驻运行通知均可停止全部介入，结束当前轮次并取消读取与系统检查计划。停止是全局停用，已接受的评分请求仍须等待唯一写入结束，不重复提交。

复习期间会临时保持 AnkiDroid 的目标牌组选择，评分或结束后按条件归还。不要同时在 AnkiDroid 或其他应用中复习、评分或切换同一集合；官方 API 没有跨应用原子事务。当前牌组、队首或复习次数改变时会拒绝提交；结果未知时先检查 AnkiDroid 历史，避免再次评分。进程被系统终止时可能无法归还原选择，但不会回放旧评分。

取卡共用一个只读槽，30秒后逻辑取消并丢弃迟到结果。真实 Anki / 文件接口可能不能立即中断，此时显示等待接口结束，槽释放前不启动另一读取；可返回或停止。媒体目录索引最多复用120秒，每张仍检查必需媒体是否可读，换目录、授权失效或读取失败会刷新。

应用使用用户启动的前台服务与普通悬浮窗，**无需无障碍权限**。它不读取其他应用的前台包名、页面或应用切换，因此其他应用的设置页、AnkiDroid 页面也可能被卡面覆盖。本应用的设置、授权配置、主动复习和更新页面期间会暂停自动介入。

## 安装与首次配置

需要 Android 11 或更新版本，以及已安装并有可复习牌组的 [AnkiDroid](https://ankidroid.org/)。当前 API 字段核对以 AnkiDroid 2.24.0 为基准，其他版本的兼容性未完整验证。

1. 从 Releases 下载 APK，在 Android 安装界面允许对应下载来源安装，然后打开“Anki 解锁复习”。首次安装默认停用自动介入。
2. 点击“授权 AnkiDroid / 刷新牌组”，同意 AnkiDroid 数据库 API 权限，并在下拉框中确认要复习的牌组。评分会写入这个牌组的真实复习记录。
3. 如使用图片、声音等媒体，点击“授权现有 collection.media 目录”，通过系统文件选择器选择 AnkiDroid 当前实际使用的媒体目录。这里只申请读取权限，不复制媒体。
4. 授权悬浮窗与运行通知，再点击“启动 / 恢复前台服务”。服务运行时会有常驻通知，可随时停止。
5. 可授权“精确闹钟”，让持续使用模式保留下一次系统检查；不授权时服务内计时仍可运行。需要熄屏亮屏复习时，必须另行明确打开“允许锁屏上亮屏显示我的卡片”。可用“测试亮屏提醒（10秒后）”检查：点击后熄屏；测试仍遵守模式、权限、时段、保护与每日上限。

纯文字卡无需媒体目录；包含媒体的卡在所需文件不可读时不会进入评分流程。卡型、模板脚本和音频的实际兼容性仍需逐项试用。

### 更新应用

0.6 没有应用内更新入口，首次升级请从上方 GitHub 或下载站下载0.82 APK并按系统提示覆盖安装，保留原设置。0.7及之后可在应用内检查更新、查看说明，再主动下载；程序校验大小、摘要、包名、精确版本和签名，用户另行点击后才打开系统安装器，最后由 Android 确认覆盖。首次需为 RecallPop 允许“安装未知应用”；授权返回后还要再次点击安装。

默认更新说明为 `https://pop.382910.xyz/update.json`，可在应用内修改为其他 HTTPS 地址。下载按版本和摘要保存独立文件，安装前重新校验；离开更新页会取消网络操作，不静默安装。更新交接已在独立 MuMu 环境完成有限闭环，真实 realme 安装器行为仍待验收。自己编译的安装包可能无法覆盖现有包，见下方构建说明。

### 媒体目录与 AnkiDroid 版本

Android 11 起，系统文件选择器限制其他应用访问 `Android/data`。Google Play 版 AnkiDroid 的媒体若位于其受限应用目录，RecallPop 无法通过自己的授权按钮解除这项限制。

媒体已经位于共享且可授权的目录时，直接选择其 `collection.media`。若位于受限目录，需要先查阅 [AnkiDroid 官方完整存储访问说明](https://github.com/ankidroid/Anki-Android/wiki/Full-Storage-Access)，确认当前安装来源、签名与数据位置，并按官方流程处理。官方 GitHub 发布的完整访问安装包标为 `full-universal.apk`；其他来源或 Parallel 版本的安装与数据位置可能不同，不能假定都可直接覆盖。正常配置 RecallPop 不需要开发者调试命令。

更换 AnkiDroid 版本或调整集合位置前，先在 AnkiDroid 完成备份与同步，按官方说明操作并确认卡片及媒体完整。不要仅为本应用直接移动、覆盖或重新导入原集合，也不要把备份包当作媒体目录选择。

### 锁屏与厂商后台限制

亮屏模式会把卡片内容直接显示在系统锁屏上，旁人可能看到；请按自己的卡片内容决定是否开启。系统锁会保留，应用不会解锁设备。实际显示后，无人触摸时最多暂保持亮屏 30 秒并退出；第一次真实触摸会取消这次保持与退出计时，之后由系统管理熄屏。退出卡片不保证立即灭屏。

部分厂商需要分别允许悬浮窗、后台运行、后台弹出界面和锁屏显示。realme UI 7 的测试中，需要检查本应用的“耗电管理 → 完全允许后台行为”“特殊应用权限 → 后台弹出界面”，以及首次锁屏显示提示；AnkiDroid 冷取卡还可能需要其“关联启动”许可。Android 原生电池“无限制”不一定代替这些厂商设置。菜单名称随系统而异，只调整相关应用的许可即可。

此前启用、开机后已完成凭据解锁且必要许可满足时，尝试在开机或覆盖更新后请求恢复前台服务。0.82还会在持续使用模式条件满足时登记下一次系统检查，进程退出后系统可重新请求服务，继续保存的累计与剩余计时；卡片可能更晚出现。仅解锁模式不安排周期恢复，缺精确闹钟许可时只保留服务内计时。用户停止会取消计划，系统强行停止后需手动打开并启动。前台服务和系统闹钟都不保证永远有效；不追补离线提醒、不把离线时间算入持续使用，异常退出可能少记最后不足5秒的使用。

主页运行状态依据当前服务实例，开启开关和旧运行记录不代表现在存活。“预计下次检查”不保证届时有到期卡或系统准时投递。没有弹卡时，可先检查状态、许可、保护期和每日上限，再查看近期运行记录和系统退出说明；说明在下次进程启动时读取，可能缺失，也不能确定所有信号终止的来源。

## 为什么尝试这种方式

项目把主动回忆放进手机使用中的短暂机会，间隔练习仍由 AnkiDroid 的调度决定。这里的具体触发频率、随机间隔、锁屏亮屏和每日目标都是实验设置；尚无证据证明这些设置优于正常使用 AnkiDroid，也不保证达到界面的每日完成目标或改善学习效果。

## 当前验证程度

0.82最终组合已有原开发环境13套主机检查、2项源码合同、离线构建及 MuMu 覆装证据。此前独立合成卡环境已验证跨牌组评分、条件归还、部分批次评分、读取取消、STOP及更新交接；0.82有限系统闹钟恢复与强停边界也已验证。本次 GitHub 整理复用一致的现成 APK，仅同步源码和运行现成源码检查，未重新构建或操作设备。详见 [0.82说明](docs/0.82-testing.md)。

真实 realme 的自然2–5分钟投递、长期待机、重启/时区切换、厂商删闹钟、secure锁屏批次、最新安装器交接、全部卡型及音频、现场媒体缓存命中与耗时、AnkiWeb 同步和 Android lint 仍未完整验收。模拟延迟和有限闹钟实验不证明真实 Binder 可中断或永久保活；AnkiDroid偶发短暂消失的提示尚未定位。0.6的 realme 短流程只作 [历史证据](docs/0.6-testing.md)，不代表新版验收。

## 构建

仓库保留与当前0.82 APK对应的运行源码。配置固定为 Java 17、Android SDK Platform 36、Android Gradle Plugin 9.4.0、Gradle wrapper 9.6.0；本项目没有额外的应用库依赖。需要能访问 Google Maven、Maven Central 和 Gradle 分发服务。

安装符合这些版本要求的 JDK 和 Android SDK，设置 `JAVA_HOME` 与 `ANDROID_HOME`，或在本地 `local.properties` 配置 `sdk.dir`。不要把个人 SDK 路径提交进仓库。原开发环境已成功执行 `assembleDebug`；发布整理时未重新运行构建，新的干净环境构建尚未验证。

Windows PowerShell：

```powershell
.\gradlew.bat assembleDebug
```

Linux / macOS：

```sh
chmod +x gradlew
./gradlew assembleDebug
```

产物为 `app/build/outputs/apk/debug/app-debug.apk`，包名 `dev.ankigate`，versionCode `16`，versionName `0.82-test`。GitHub 标签 `v0.82.0-test` 对应该应用版本；GitHub自动提供源码 ZIP / tar.gz。

Releases 当前提供的是可调试的试用 APK，没有承诺长期固定的正式发布证书。自己构建的 APK 通常使用自己机器上的调试签名；签名不同就不能覆盖安装本仓库发布的同包名 APK。不要为了覆盖安装而直接卸载，卸载会丢失本应用的牌组选择、媒体授权和统计；AnkiDroid 集合由 AnkiDroid 管理。构建 release 版本需要自行配置并妥善保管签名密钥，密钥不属于本仓库。

## 权限与数据

AnkiDroid 数据库权限用于读取到期卡及写入用户评分；悬浮窗用于普通卡面；通知与前台服务用于明确显示运行状态；精确闹钟用于下一次使用检查和可选亮屏流程，短时 CPU 唤醒锁用于亮屏交接。开机权限用于已启用状态的恢复请求，安装来源权限用于用户确认的系统覆盖安装。网络权限用于更新及卡片模板可能引用的网络内容。

本项目没有账户、分析 SDK 或后台服务器，不建立第二份集合数据库，不复制现有媒体。牌组选择、媒体目录授权、开关和本应用统计保存在本机。近期记录最多60条，不保存卡面、媒体名或卡片身份；系统退出说明最多320字符并清理常见路径和 URI，系统文字格式仍可能变化。“复制记录”只写本机剪贴板，不自动发送。开发调试输出仍可能包含卡片标识与评分状态，反馈前请检查并清除个人内容、目录与设备标识。
